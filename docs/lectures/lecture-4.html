01 · Attention as content lookup

A query asks each key how relevant it is

Imagine a sentence encoded as vectors. A query describes what a position needs; each key describes what a position offers. Their dot product is a relevance score. Softmax makes weights sum to one, and those weights blend the corresponding value vectors.

TOY EXAMPLE: FIND THE B
tokensA · A · B · A
←
queryq = [0,1]

If A=[1,0] and B=[0,1], their dot products with a B-seeking query are 0,0,1,0. The B position gets the largest weight.

Interactive attention weights

Increase B-key strength to make attention more selective.

“Scaled dot-product attention” divides scores by √dₖ. Without scaling, dot products tend to grow in magnitude with key/query dimension, making softmax too peaked and its useful gradients weaker.

02 · Self-attention and multiple heads

Every token can be a query, key, and value

In self-attention, the same input sequence is projected three ways: Q asks; K is matched; V carries content. An attention matrix has one row per query position and one column per key position. The output at a position is a weighted combination of value rows.

03 · Transformer block

Mix across positions, then transform each position

A decoder block uses masked self-attention followed by a position-wise feed-forward network. Residual additions preserve a direct information path. Normalization controls activation scale. A stack applies several blocks to form increasingly contextual token representations.

The attention sublayer changes what each position knows by mixing information over T. The MLP changes each position’s feature vector independently; it does not mix time positions. Transformer implementations commonly use an expansion to dff and project back to dmodel.

Projection cost

A dense D→D projection per token costs proportional to D². For B sequences and T tokens: roughly O(B·T·D²).

Attention score cost

Each token compares with T keys: roughly O(B·H·T²·dₕ)=O(B·T²·D). Longer context raises this quadratically.

04 · Position information

Attention needs a clue about token order

Self-attention by itself is permutation-equivariant: shuffle token vectors and attention shuffles their outputs the same way. Add position information so the model can distinguish “dog bites person” from “person bites dog.”

05 · Next-token training and masking

Train many positions in parallel without cheating

Input tokens are shifted against targets. For “I saw the dog running,” a model receives “START I saw the dog” and predicts “I saw the dog running.” The loss is evaluated at many positions in one forward pass. This parallel training does not mean future-token information is allowed.

InputSTART · I · saw · the · dog
↓ Transformer
TargetI · saw · the · dog · running

With ordinary self-attention, position “I” could attend to “saw” and directly leak its target. The causal mask blocks the upper triangle of the score matrix: row i can use columns j≤i only.

Revision check

Shape and concept quick checks

Q=[B,H,T,dₕ] and K has the same shape. What are score dimensions?

[B,H,T,T]: query positions against key positions.

For D=128 and H=8, what is dₕ?

128/8=16 features per head.

Why divide scores by √dₖ?

To prevent dot-product scale from growing too large and softmax from becoming overly sharp.

What causes future-token leakage during training?

Unmasked self-attention lets a token read later tokens that are supposed to be its prediction targets.

Why does attention need position information?

Without it, attention has no built-in indication of token order; positional signals distinguish arrangements.

What does multi-head attention add?

Several independently projected attention patterns, concatenated and mixed by an output projection.
