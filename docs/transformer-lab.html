01 · Dimension playground

Make tensor shapes feel concrete

A shape is a list of counts. [B,T,D] means B examples, T token positions in each, and D numbers describing each token. Adjust the controls and follow the same data through the model.

Click a stage

The dimensions tell us how many items and features exist. A reshape may reorganize axes without changing the number of values; a projection changes the feature width.

A reliable way to read a shape

B — how many independent examples are processed together.

T — positions/tokens in each sequence.

D — features per token. Split across H heads: dₕ=D/H.

Example: if B=2,T=8,D=128,H=8, then each head has 16 features; attention scores have shape [2,8,8,8]. The last two 8s are query-position × key-position.

Slicing

[0,-1,:] means first example, last token position, every feature. Starting [B,T,D], result is [D].

Unsqueeze

Insert a length-1 axis. [N] → unsqueeze(-1) → [N,1], useful for gather indices.

Squeeze

Remove a length-1 axis. [N,1] → [N]. Specify the axis so a batch of size one stays a batch.

02 · Position inside attention

RoPE: turn position into a gentle spin

Without position information, attention sees token vectors but not their order. RoPE rotates pairs of query and key features by an angle tied to token position. That changes which query/key pairs match, so the same word representation can behave differently at different places.

The benefit: a query/key dot product now contains information about their relative positions. Different feature pairs rotate at different speeds. θ sets how those frequencies are spread across the head.

Each even/odd feature pair is a 2-D coordinate. RoPE applies the rotation to Q and K, not V. Low-frequency pairs turn slowly; high-frequency pairs turn faster.

03 · Feature refinement

SwiGLU: let features pass through a learned gate

Attention mixes information between token positions. The feed-forward layer then works within each position. SwiGLU expands the feature vector, computes a gate and a value, multiplies them, then compresses back to the original width.

WHY A GATE?

A plain MLP transforms features. The gate adds a second learned signal that controls how much of each transformed value continues.

w1 makes the gate signal D → F
w3 makes the candidate value D → F
w2 mixes gated features back F → D

SiLU(z)=z·sigmoid(z): it smoothly suppresses negative gate values and lets positive values through. ⊙ means multiply matching feature-by-feature.

04 · Context mixing

Attention: choose which earlier tokens matter

For each token, the query compares with keys to get relevance scores. Softmax turns scores into weights. The token then takes a weighted blend of values. In next-token prediction, a causal mask blocks future positions so the model cannot peek at the answer.

scores = QKᵀ / √dₖ → mask → softmax → weights × V

Scaling by √dₖ keeps scores from growing too large as head width grows. Multiple heads learn separate match patterns; concatenate their outputs and project back to D.

05 · Stable signal through depth

RMSNorm + residual: keep a usable path

Stacking many transformations can make activation scales hard to manage and gradients hard to pass. RMSNorm rescales each token’s features. A residual connection adds the block’s update to the original stream, so the layer can learn a correction instead of rebuilding everything from scratch.

06 · Train the prediction

Cross-entropy: reward the correct next token

The model emits one logit per vocabulary item. Softmax turns logits into probabilities; cross-entropy asks how surprising the correct token was. A confident correct answer has low loss; a confident wrong answer has high loss. Subtracting the largest logit before exponentiating prevents overflow.

Training loop: sample input and one-token-shifted targets → forward pass → loss → backward() → clip gradients → optimizer step. A warmup + cosine schedule raises learning rate gradually, then smoothly lowers it.
